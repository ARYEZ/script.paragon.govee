v1.1.1
- "Capture lights as a scene..." is now on the main menu as well as inside
  Scenes, where it was easy to miss.
- The main menu title shows the running version, so a `git pull` can be
  confirmed at a glance.
- Main menu rows are now (label, handler) pairs like the rest of the menus,
  which removes the last place where inserting a row could rewire the ones
  below it.

v1.1.0
- New "Capture lights as a new scene..." in the Scenes menu. It snapshots what
  every light is doing right now and saves it as a scene. This is the way to
  get a Govee Tap-to-Run into Kodi: run it in the Govee app, then capture the
  result. The saved copy replays over the LAN, so it needs no Govee account
  credentials and no cloud call.
- Scenes can now carry a different setting per light, not just one uniform
  setting for all of them. Scenes without per-light entries are unchanged, and
  a light with no entry falls back to the scene's own values.
- Added bulk status reads: the whole set of lights is queried in one pass
  instead of one bind and one timeout each. Capturing 25 bulbs now costs about
  one timeout rather than the better part of a minute.
- Cloud and LAN state readings are now normalised onto the same keys. The
  cloud reported powerState where the LAN reported onOff, which pushed the
  difference onto every caller.

v1.0.2
- LAN search now sends the scan from every local interface rather than only
  whichever one the routing table prefers, which is what broke discovery on
  multi-homed boxes (VPN, Hyper-V or docker bridge, wired plus wireless).
- Added a plain broadcast fallback alongside the multicast scan, for networks
  that drop or fail to flood 239.255.255.250.
- New "Diagnose LAN search..." tool in the control panel, also reachable as
  RunScript(script.paragon.govee,action=diagnose). It distinguishes the reply
  port being held by another program, the scan failing to send, replies that
  are not Govee, and total silence, and writes the full detail to kodi.log.
- A failed bind on UDP 4002 now names the likely culprit instead of reporting
  a generic error.
- Fixed the diagnostic device count including one entry per probe path, which
  would have reported several times the real number of lights.

v1.0.1
- Fixed the background service crashing on startup with "TypeError: an
  integer is required". Kodi parses xbmc.Player constructor arguments in the
  base type, before a subclass __init__ runs, so the player subclass must
  take no arguments; the service now attaches itself after construction.
- Player callbacks are inert before the service attaches and after it
  detaches, so a callback arriving during startup or shutdown is a no-op.
- Test stubs now reproduce Kodi's constructor-argument parsing for both
  xbmc.Player and xbmc.Monitor, so this class of failure is caught off-device.

v1.0.0
- First release.
- Govee LAN transport: multicast discovery, power, brightness, colour, colour
  temperature and status, with no API key and no rate limit.
- Govee Cloud transport as a fallback for lights without LAN Control.
- Automatic per-device transport selection; LAN preferred when available.
- Devices found on both transports are merged into one entry.
- Control panel: per-light and all-lights power, brightness, colour and colour
  temperature, plus device rename, enable/disable and identify.
- User-editable scenes, seeded with Movie Night, Paused, Lights Up,
  Warm Evening, Paragon Purple and All Off.
- Playback lighting service: applies scenes on play, pause and stop, with
  content-type, fullscreen and delay filters. Only restores on stop if it was
  the thing that dimmed the lights.
- RunScript() actions for keymaps and favourites, with optional per-light
  targeting by name or device id.
